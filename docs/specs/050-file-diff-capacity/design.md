## 已选择方案（2026-11-15）

基于负责人“可以”继续实施，使用两条Uint16Array滚动LCS行、每对行1bit删除/新增决策回溯。相同行直接匹配，非相同处next[j]>=current[j+1]时记录删除，否则新增，严格复现031择优。最大位图约2.98 MiB，加滚动行/行ID约60KB；这是明确分配预算，不是浏览器总内存实测。拒绝超过5000行后才分配。相同文件无需位图，行ID把长字符串内层比较改为整数。相比Hirschberg，该方案非线性空间，但有界低内存且保留已批准重复行语义，无需改变用户配对规则；原候选算法阻塞据此解决。

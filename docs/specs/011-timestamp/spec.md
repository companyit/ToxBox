# 011 时间戳转换

日期：2026-11-03。状态：2026-11-03 负责人明确授权实现，已完成本地功能；跨浏览器完整矩阵及负责人最终验收尚未全部完成。按 Base64 → 时间戳 → UUID → 工具搜索顺序推进。关联产品需求 P1-10。

## 目标、范围与验收

用户明确选择秒或毫秒，在 Unix 时间戳与日期间双向转换，拟路径 `/developer/timestamp/`。

| 编号 | 可执行验收条件 |
| --- | --- |
| TIME-01 | 默认秒、UTC；支持秒和毫秒整数及负数，不根据位数猜测；时间戳 `0` 对应 UTC `1970-01-01 00:00:00.000`，秒 `1` 与毫秒 `1000` 结果一致 |
| TIME-02 | 日期输入采用显式 `YYYY-MM-DD HH:mm:ss.SSS`（年份 0001～9999），严格核验闰年、天数及时间；仅支持 UTC 和固定 UTC+08:00，界面明确标注，不依赖设备时区或宽松 Date 字符串解析 |
| TIME-03 | 时间戳仅接受可安全表示的十进制整数、可选负号，拒绝指数、小数和超范围值；输出日期须处于上述年份范围；毫秒转秒向负无穷取整，`-1` 毫秒对应 `-1` 秒，说明精度损失 |
| TIME-04 | 单字段最多 64 UTF-16 码元；空输入无结果，超限或非法值中文提示并保留输入；修改输入、单位、时区或方向立即清除旧结果 |
| TIME-05 | 示例、清空、复制及失败手动复制可用；全部本地处理，不存储或采集内容；独立入口、预渲染正文及 noindex |

排除：自动识别单位、设备本地时区、IANA 时区与夏令时、自然语言日期、实时时钟和新增依赖。

## 共同质量要求

## 2026-11-20 分钟精度输入优化

用户通常只知道日期、小时和分钟。负责人于 2026-11-21 要求继续开发，按 TIME-06 实施，调整 TIME-02 的日期输入范围。

| 编号 | 可执行验收条件 |
| --- | --- |
| TIME-06 | 日期转时间戳时，支持直接选择日期并填写小时和分钟。高级输入可选填秒和毫秒，留空分别按 `00`、`000` 计算。粘贴输入兼容 `YYYY-MM-DD HH:mm`、`YYYY-MM-DD HH:mm:ss` 和现有完整格式。默认示例使用分钟精度。 |
| TIME-06 验收 | UTC 秒模式下，`1970-01-01 00:01` 输出 `60`；启用精确输入后，UTC 毫秒模式下，`1970-01-01 00:01:02.003` 输出 `62003`；UTC+08:00 秒模式下，`1970-01-01 08:01` 输出 `60`。非法日期、小时 24 或分钟 60 均报错并保留输入。 |

沿用已有秒／毫秒单位和 UTC／固定 UTC+08:00 的换算语义。反向转换保留完整的日期时间精度。

TIME-07（负责人要求）：日期选择器和文本输入同时可用，共用同一日期值。选择后填入标准分钟格式，手输合法值同步到选择器，非法草稿保留供修正。

TIME-08（负责人要求）：优化时间戳工具操作区。结果单独占一整行，位于输入和转换操作下方。日期方向并排摆放手输与选择控件，空间不足时折行。现有转换、键盘和复制路径继续可用。

TIME-08 补充：多行输入和结果区域初始至少容纳四行文本，首次打开时文本框内部无滚动条，长内容仍可滚动或拉高。

TIME-09（页面体验优化）：手输格式放在输入框旁，选择器说明同步行为。结果区显示当前时区或时间戳单位，空结果给出下一步提示；错误与成功状态仍可播报。

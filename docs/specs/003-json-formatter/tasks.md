## 纯函数明确预期（J01～J25 本轮已执行通过）

表中 `\n`、`\t` 表示实际控制字符；转义字符串案例另作说明。凡返回错误，必须没有 output，原输入不被改写。输出完整字符串按 JSON.stringify 的规则精确断言，不只断言能再解析。

| 用例 | 输入/操作 | 预期 |
| --- | --- | --- |
| J01 | 空串；仅 ` \t\r\n`；分别三种操作 | empty，不解析为 null |
| J02 | U+00A0、U+FEFF 或 U+3000 + `{}` | invalid-json，不主动剥离 |
| J03 | `{"a":1}`，格式化2/4 | 分别 `{\n  "a": 1\n}`、`{\n    "a": 1\n}`；无末尾换行 |
| J04 | `[]`、`[1,true,null]`，校验/压缩 | 校验 validated 无输出；压缩分别原样 |
| J05 | JSON 字符串 `"你好"`；数字 `42` | 分别校验成功；压缩为 `"你好"`、`42` |
| J06 | `true`、`false`、`null`、`0` | 六类顶层测试的补充；均成功，压缩输出对应文本 |
| J07 | `{"a":}`、`{"a":1,}`、`[1,]`、单引号、注释 | invalid-json，固定中文错误，不显示原始 SyntaxError |
| J08 | `undefined`、`NaN`、`Infinity`、`01`、`1n`、两个顶层值 `{}[]` | invalid-json |
| J09 | 合法 JSON 前后仅四类 JSON 空白 | 成功，输出不含包围空白 |
| J10 | `{"a":[1,{"b":true}]}`，格式化2/4 | 精确等于两种缩进的原生输出，结构不变 |
| J11 | 带结构空白的 `{"s":"a  b"}` 压缩 | `{"s":"a  b"}`，字符串双空格保留 |
| J12 | `{"a":1,"a":2}`；`{"a":1,"\u0061":2}`（源码含单反斜杠转义） | 压缩均 `{"a":2}`；静态重复键提示在组件中验证 |
| J13 | `9007199254740991`、`-9007199254740991` | 可转换，输出对应整数 |
| J14 | `9007199254740992`、`9007199254740993`、`-9007199254740992`；嵌套同值 | 校验 validated；格式化/压缩 unsafe-integer，无舍入后的可复制输出 |
| J15 | `1e400`、`{"n":-1e400}` | 校验 validated；转换 non-finite-number，不输出 null |
| J16 | `1.0000000000000001`、`1e-400`、`-0`、`1.00` | 压缩分别 `1`、`0`、`0`、`1`；静态精度提示不可隐藏 |
| J17 | 源码 `"\u4F60"`、`"😀"` | 压缩分别 `"你"`、`"😀"`；不保持原转义写法 |
| J18 | 源码含 `\n`、`\t`、`\"`、`\\` 的 JSON 字符串 | 解析后值不变，重新序列化有合法转义；原始未转义换行则 invalid-json |
| J19 | 源码 `"\ud800"`；`"e\u0301"` | 孤立代理项压缩为小写 `"\ud800"` 转义；后者含 e+组合符，不变成预组合 é |
| J20 | `{"__proto__":{"x":1},"2":"b","1":"a"}` | __proto__ 作为自有属性保留，无 Object.prototype 污染；输出数字键1在2前，不承诺原序 |
| J21 | `"`+99998个a+`"`；再加一个a | 长度100000允许；100001 input-too-large，Emoji按双码元另参数化 |
| J22 | 100/101 层数组包裹0；字符串内 `[[` 与转义引号 | 100层允许，101层 too-deep；字符串括号不计层，转义引号不提前结束字符串 |
| J23 | 输入限内、100层内生成格式化输出 >1000000 的嵌套/多值样本 | output-too-large；≤1000000允许；纯输出长度保护辅助函数另测999999/1000000/1000001，样本长度生成后显式断言 |
| J24 | 对 parse/stringify 临时注入意外异常并恢复 | unexpected，无输出、无原始错误信息；随后合法输入可成功，不修改源码模拟失败 |
| J25 | `{"n":1e400,"n":1}`；同时含不安全整数和非有限值 | 前者压缩 `{"n":1}`，静态警示保留；后者转换 non-finite-number，错误优先级确定 |

## 本轮审批与数值方案审查（2026-10-10）

来源：项目负责人《M1-03 JSON 工具规格审批与编码授权》。已批准六类顶层值、手动操作、100000码元、原生JSON与独立纯函数、只读结果、本页试用与预留路径、复制回退及结果失效。保留规格100层/1000000输出保护和设备性能验证方案；预算未测不宣称满足。本节记录当前授权结论，不授权生产发布。

数值策略采用原规格“最终解析值”检查：校验仅确认语法；转换拒绝非有限数与不安全整数。有限小数的舍入、下溢、科学记法/负零变化按原生语义处理，始终显示精度警告，绝不宣称无损或完整原数字安全。要求精确数字的用户须保留原文并用JSON字符串表示。不使用正则检测数值或自行实现解析器；重复键后值覆盖，被覆盖值不参与最终树检查。

已研究 JSON.parse reviver context.source：[MDN兼容性数据](https://github.com/mdn/browser-compat-data/blob/main/javascript/builtins/JSON.json)列出Chrome114起、Edge镜像Chromium、Firefox135起、Safari18.4起支持；这是文档支持信息，不是本机四浏览器实测。该能力能提供原始primitive源码，但不会自动实现任意精度转换。本方案不依赖它，不使用JSON.rawJSON或polyfill；有/无context.source的浏览器都执行同一最终值检查和警告，没有静默弱化的回退。浏览器两个主版本完整验收仍待验证。参考 [MDN JSON.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse)。

审查：需求与验收一致，J14～16/J25覆盖数值拒绝与有损边界，J21～24覆盖资源/异常；无需额外依赖。已批准方案不要求无损小数或保留重复键，因此不存在阻止本轮编码的数值技术阻塞。如将目标改为检测/拒绝全部精度损失，应另行评审，不能把当前警示方案当作该能力。

# 003 JSON 格式化与校验需求规格

状态：M1-03 / Implement + Verify，2026-10-10，项目负责人已批准规格与编码，数值方案审查结论见下文。前置：[002 任务](../002-text-statistics/tasks.md) 已满足 Dev Done，Release Ready 未完成。依据：[产品 P1-04、06～08](../../product/requirements.md)、[架构决策](../../architecture/decisions.md)、[质量门禁](../../quality/gates.md)。本轮授权以批准范围为准，不新增依赖或发布。

## 目标与范围

在浏览器本地校验 JSON，按 2/4 空格格式化或压缩，复制转换结果；空输入可填示例，可清空输入与结果，兼顾手机与桌面。默认 2 空格符合 P1-04，4 空格为本轮补充范围。使用显式按钮执行，不在每次键入时解析。

不包含 JSON5、注释、尾逗号容错、自动修复、Schema 校验、文件导入、键排序、差异比较、无损数字解析、账户、持久化、后台或第三方服务。不改动文本统计算法或交互。

## JSON 语义与资源边界

- 空字符串与仅含 JSON 空白（U+0020、0009、000A、000D）均提示“请输入 JSON”，不视为合法 JSON。NBSP、BOM、全角空格不先 trim/删除，作为非法 JSON；不沿用文本统计 W 集合。原输入始终保留。
- 顶层对象、数组、字符串、数字、布尔值、null 均允许。校验成功仅表示语法合法，不保证业务结构或无损转换；校验操作清除先前输出，不产生可复制结果。
- 非法 JSON 返回统一中文提示“JSON 语法错误，请检查引号、逗号或括号”。不直接显示浏览器 SyntaxError.message，避免泄漏输入及跨浏览器文案漂移；首版不承诺定位行列。
- 重复属性名遵循原生解析：同名键最后一个值覆盖前值（包括转义后同名），不检测/警告具体位置，不保留重复键。始终可见提示“重复属性名仅保留最后一个值；转换可能改变数字精度和原始写法，请保留原文。”不声称无损。重复键中被覆盖的数字不进入最终值检查。
- 数字使用 JavaScript Number。安全整数范围为 ±9007199254740991；格式化/压缩遇到最终解析值中的非安全整数时拒绝输出，提示“存在超出安全整数范围的数字，无法安全转换；如需精确保留，请在原数据中使用字符串。”不把数字自动改为字符串或 BigInt。语法校验仍可成功，同时提示“语法合法不代表数字精度安全”。
- 最终解析值中出现非有限数（例如 1e400）时校验语法可成功，但格式化/压缩拒绝输出并提示数字范围错误，不允许悄悄转换成 null。有限小数仍可能舍入/下溢，不能完整检测原文精度损失；例如 1.0000000000000001 转换为 1、1e-400 为 0，必须依靠上述始终可见精度提示，不宣称全部高精度值无损。-0 转换为 0，指数记法和尾随零可变化。
- Unicode/转义按原生 JSON 规则解释，不执行 NFC/NFKC，不处理为 HTML。转义写法不保证保留，例如源码 `"\u4F60"`（单反斜杠 Unicode 转义）解码后可输出为中文；孤立代理项输出为转义序列。键顺序遵循原生序列化规则，整数索引键可重排，不承诺原文本顺序/字节一致。
- 格式化使用 2 或 4 个 ASCII 空格，换行 LF，无额外末尾换行；压缩只去除结构空白，字符串内空格、换行语义不丢失。改变缩进清除旧输出，需要重新格式化；压缩不受所选缩进影响。
- 输入上限为 100,000 UTF-16 码元（按 string.length），100000 可处理、100001 超限：保留全部原文，清空结果和旧成功提示，不解析、不截断；缩短后须显式重试。
- 容器嵌套上限为 100 层（顶层对象/数组为第 1 层），解析前线性扫描，仅统计字符串外的 {/[ 与 }/]，正确跳过转义引号。超过上限返回资源限制错误；扫描不代替语法校验，不自动修复括号。该保护可能优先于非法语法错误。
- 序列化结果上限为 1,000,000 UTF-16 码元，超限不展示/复制，保留输入并提示缩小内容。100 层与输入限额共同约束中间输出；输出限额为生成后的展示保护，不宣称同步 API 可以被超时中断。捕获意外运行/资源异常，显示中文通用错误，原文不丢失。
- 发布性能预算提案：生产预览在 Mac mini M4 与记录型号的真实手机上，10k/100k 码元的平坦对象、混合 Unicode 数组和深层样本，各操作各连续测 10 次；纯函数每次 ≤100ms，按钮触发至结果绘制每次 ≤300ms。保留逐次耗时与最大值，不用平均值替代；未测不宣称通过。无强制超时保证，若不达标先评审，不能自行添加 Worker/依赖。

技术语义参考：[ECMAScript JSON.parse](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.parse)、[JSON.stringify](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.stringify)。本规格在原生语义之上增加资源和数值拒绝策略；不依赖新版本 reviver context/source 能力。

## 需求与验收条件

| 编号 | 行为 | 可验证验收条件 |
| --- | --- | --- |
| JSON-01 | 输入与校验 | 有标签的输入框支持键入/粘贴；显式校验；空/纯 JSON 空白有提示；六类顶层值可校验；非法输入保留，旧结果清除；输入法组合期间禁止执行 |
| JSON-02 | 格式化 | 默认 2 空格，可选 4 空格；输出严格等于批准语义的原生格式化结果，无尾换行；改缩进清除旧结果 |
| JSON-03 | 压缩 | 输出紧凑合法 JSON，保留字符串内部空白语义；与缩进选择无关 |
| JSON-04 | 数值/重复键/Unicode | 按上述规则覆盖重复键、禁止非安全整数/非有限值转换；静态精度与重复键提示始终可见；支持转义/代理项，不宣称无损 |
| JSON-05 | 结果有效性 | 任意编辑（含组合开始）、操作开始、改缩进、失败立即清空旧输出与复制提示；只有当前输入转换成功的结果可复制；校验成功无输出、复制禁用 |
| JSON-06 | 复制及竞态 | 仅复制只读结果全文；空结果禁用；Promise 成功才反馈成功；失败/API 缺失/非安全上下文聚焦并全选结果，提示手动复制，不读取剪贴板、不用 execCommand；等待中禁止重复复制；编辑、清空、重算、改缩进、卸载后旧反馈不得写回，输入不变 |
| JSON-07 | 示例与清空 | 示例只在原输入严格为空且非组合时启用，处理函数再次防覆盖；示例只填输入不自动转换；清空同时清除输入/结果/错误/提示并聚焦输入，重置缩进为 2；全部初始状态时清空禁用 |
| JSON-08 | 限额与异常 | 码元100000/100001、嵌套100/101、输出上限与超限边界明确验证；超限/异常无旧输出且保留原文，修正后可重试；发布性能按预算实测 |
| JSON-09 | 本地与生命周期 | 无登录/上传/日志/URL/存储输入；使用文本绑定不用 v-html/eval/Function；刷新、收起卸载后重入恢复空输入/结果、2 空格；不触发离开确认或保存 |
| JSON-10 | 布局与集成 | CSS Variables、明暗模式、375×812/768×1024/1440×900无页面横向溢出；标签、可见焦点、键盘操作、polite 反馈和200%缩放；正式 URL 预留 /developer/json-formatter，仅预留，未安装路由不伪造地址；本页试用真实分区复用唯一 main/h1，不改变文本统计 |

## 本轮审批与数值方案审查（2026-10-10）

来源：项目负责人《M1-03 JSON 工具规格审批与编码授权》。已批准六类顶层值、手动操作、100000码元、原生JSON与独立纯函数、只读结果、本页试用与预留路径、复制回退及结果失效。保留规格100层/1000000输出保护和设备性能验证方案；预算未测不宣称满足。本节记录当前授权结论，不授权生产发布。

数值策略采用原规格“最终解析值”检查：校验仅确认语法；转换拒绝非有限数与不安全整数。有限小数的舍入、下溢、科学记法/负零变化按原生语义处理，始终显示精度警告，绝不宣称无损或完整原数字安全。要求精确数字的用户须保留原文并用JSON字符串表示。不使用正则检测数值或自行实现解析器；重复键后值覆盖，被覆盖值不参与最终树检查。

已研究 JSON.parse reviver context.source：[MDN兼容性数据](https://github.com/mdn/browser-compat-data/blob/main/javascript/builtins/JSON.json)列出Chrome114起、Edge镜像Chromium、Firefox135起、Safari18.4起支持；这是文档支持信息，不是本机四浏览器实测。该能力能提供原始primitive源码，但不会自动实现任意精度转换。本方案不依赖它，不使用JSON.rawJSON或polyfill；有/无context.source的浏览器都执行同一最终值检查和警告，没有静默弱化的回退。浏览器两个主版本完整验收仍待验证。参考 [MDN JSON.parse](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/JSON/parse)。

审查：需求与验收一致，J14～16/J25覆盖数值拒绝与有损边界，J21～24覆盖资源/异常；无需额外依赖。已批准方案不要求无损小数或保留重复键，因此不存在阻止本轮编码的数值技术阻塞。如将目标改为检测/拒绝全部精度损失，应另行评审，不能把当前警示方案当作该能力。

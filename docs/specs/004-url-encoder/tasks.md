## 纯函数测试向量（U01～U30 已执行通过）

缩写CE=组件编码、CD=组件解码、UE=完整URI编码、UD=完整URI解码。“两种编码/解码”须分别参数化执行。“错误”必须没有output、不附输入/原异常；所有测试输入不可变。`\n`、`\r`、`\t`、`\uXXXX`表示实际码元，百分号为原文字面字符。

| 编号 | 输入与操作 | 精确预期 |
| --- | --- | --- |
| U01 | 空串，CE/CD/UE/UD | empty无内容状态（不是错误），结果不存在；函数不调用原生处理 |
| U02 | `AZaz09-_.!~*'()`，两种编码 | 原样不变 |
| U03 | `你好`，两种编码 | `%E4%BD%A0%E5%A5%BD` |
| U04 | `😀`，两种编码 | `%F0%9F%98%80` |
| U05 | `;/?:@&=+$,#`，CE | `%3B%2F%3F%3A%40%26%3D%2B%24%2C%23` |
| U06 | 同U05，UE | `;/?:@&=+$,#`原样 |
| U07 | `[]`，两种编码 | `%5B%5D` |
| U08 | U05的百分号串，CD/UD | CD=`;/?:@&=+$,#`；UD=原百分号串 |
| U09 | `%2f%3f%23%41`，CD/UD | CD=`/?#A`；UD=`%2f%3f%23A`（原保留转义大小写不变） |
| U10 | `a b+c`，CE/UE | CE=`a%20b%2Bc`；UE=`a%20b+c` |
| U11 | ` \t\n`，两种编码 | `%20%09%0A`，不trim |
| U12 | `a+b%20c%2Bd`，CD/UD | CD=`a+b c+d`；UD=`a+b c%2Bd`；+不变空格 |
| U13 | `%`、`%2`、`%GG`、`a%4Zb`、`%u4F60`，两种解码 | invalid-encoding，整次失败 |
| U14 | `%E4%BD`、`%F0%9F%98`、`%E4x%BD%A0`，两种解码 | invalid-encoding，不返回已解前缀 |
| U15 | `%80`、`%C0%AF`、`%E0%80%AF`、`%F4%90%80%80`、`%FF`，两种解码 | invalid-encoding（独立续字节/过长/越界/非法首字节） |
| U16 | `%ED%A0%80`、`%ED%B0%80`，两种解码 | invalid-encoding，不接受UTF-8编码的代理项 |
| U17 | `%e4%bd%a0%f0%9f%98%80`，两种解码 | `你😀`，接受小写转义 |
| U18 | `%25`，两种解码 | `%`，不再尝试下一轮解码 |
| U19 | 原文`%2F`，两种编码 | `%252F`，不保留已有百分号转义 |
| U20 | `%252F`先CD/UD；手动将结果再CD/UD | 首轮两者=`%2F`；第二轮CD=`/`，UD=`%2F` |
| U21 | `%`先编码，再手动将结果编码 | 两模式首轮`%25`、次轮`%2525`；原输入不变时重复执行仍首轮结果 |
| U22 | `https://example.com/路径?q=a+b#片段`，两种解码 | 未转义原文不变，不验证/访问此地址 |
| U23 | `\uD800`、`\uDC00`、`a\uD800b`、高高/低高非法组合，两种编码 | invalid-unicode，原字符串保留 |
| U24 | 原样`\uD800`、`\uDC00`与`x%41\uD800`，两种解码 | 按码元原样保留前两者；第三者=`xA\uD800`，不声称Unicode校验成功 |
| U25 | `%3Cscript%3Ealert(1)%3C%2Fscript%3E`，CD | `<script>alert(1)</script>`仅作为字符串；组件验证不执行/不生成HTML |
| U26 | 100000个a与100001个a，四种操作 | 前者ok、output原样；后者input-too-large；超限不调用原生API |
| U27 | 50000个😀、再加a，两种编码 | 前者码元100000、output=`%F0%9F%98%80`重复50000次；后者超限。100000个`你`编码输出900000码元，验证空间上界 |
| U28 | `%41`重复33333次再加a（100000），再加a | 两种解码前者=`A`重复33333次加a；后者超限；边界先于转义解析 |
| U29 | 对四个原生API分别临时注入Error并恢复 | unexpected且无输出/原错误消息；恢复后`abc`各操作成功。URIError另测按动作映射，失败不污染下一调用 |
| U30 | `e\u0301`与`é`，两种编码；`%0D%0A%00`解码 | 前者`e%CC%81`、后者`%C3%A9`，不规范化；解码为CR/LF/NUL三个码元。另测`%252G`首轮=`%2G`，手动第二轮失败，禁止递归 |

U25的UD额外预期为`<script>alert(1)<%2Fscript>`；UI安全验证以CD完整HTML文本为主。正常Unicode样本可补充编码再解码往返属性，但不得用往返代替上述固定预期；UD保留结构转义等场景不假设所有字符串双向规范化一致。

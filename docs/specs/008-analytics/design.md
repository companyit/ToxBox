# 008 页面访问分析设计（本轮授权实现）

关联：[规格](spec.md)、[任务](tasks.md)、[ADR-022](../../architecture/decisions.md#adr-022ga4-页面访问分析待确认)。

## 模块与数据流

拟新增独立客户端分析模块，由 src/main.ts 在路由就绪后初始化；不在 HTML 中直接粘贴默认自动采集片段。构建时 SSR 不执行模块初始化。生产环境判定复用现有环境契约，实施前核对，禁止把本地 production 构建自动等同于正式站点。

路由成功导航 → 页面目录白名单映射 → 固定 origin/路径/标题 → 手动 page_view。初次页面只由一个入口上报。关闭默认自动 page_view；Google 后台增强型衡量及 referrer 处理需按官方文档核实，不能让自动采集绕过白名单。未知路径统一映射固定 404，不从 URL 或页面输入拼接事件参数。

## 状态和异常

初始化和外部脚本单例；加载失败不影响主应用，不输出用户数据。是否需要同意状态与拒绝后的撤销流程，待负责人确认后补充，当前不擅自决定 Cookie 策略。

## 验证

实施前查阅 Google 官方接入和 SPA 文档。用请求拦截验证首次加载、路由切换、重复导航、含敏感 query/hash/referrer 与未知路径；断言发出的全部请求没有测试敏感字符串。验证 preview/dev/SSR 零分析请求、加载失败下工具可用，执行类型检查、构建及浏览器验收。真实 GA 接收与后台设置单独记录，拦截测试不能替代。

## 2026-11-02 实施记录

负责人后续明确要求“进行代码修改，需要开始监听”，据此批准本轮页面统计接入。采用直接启用与默认 GA 标识符存储，不新增同意弹窗；隐私页已披露。复用现有 production SEO 环境并核对实际 origin，不在 preview/local 启用。监听放在客户端 mount 后，未改动构建或发布脚本。

已实现手动页面上报及脱敏、重复初始化和同一页面 query/hash 导航去重。Google 后台增强型衡量仍需关闭或核验，否则自动事件可能绕过手动策略；不能宣称真实所有网络请求已完成隐私验收。官方依据：https://developers.google.com/analytics/devguides/collection/ga4/views 。未访问或修改 GA 后台，未部署。

## ANA 启用条件修正（2026-11-02）

针对 Google 未检测到标签的反馈，修正统计与 SEO 模式的耦合：统计使用 Vite 发布构建标记与实际 origin `https://www.v7luck.com` 双重判断，不再要求 SEO production。这样 build:csr 产物上传正式站点后也可启用；本地开发及本地/其他域名预览不启用。此前“所有 preview 构建均禁用”的条款由本条替代，preview SEO 构建若部署正式域名会统计。SEO 索引与发布流程不变，不执行部署。

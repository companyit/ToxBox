# 015 办公文本整理（提案）

日期：2026-11-03。负责人希望继续补充常用办公功能。本提案建议先增加本地文本整理，优先级与详细范围待负责人审阅确认；不将方向性需求视为所有细节获准实现。关联产品需求 P1-13。

## 目标与场景

办公用户从邮件、文档或表格中复制名单、编号或多行文字后，希望清理空白、去重、排序或批量替换，再复制回自己的应用。拟路径 `/office/text-cleanup/`，与已有文本统计互补。全程在浏览器内完成，不上传文件或输入内容。

## 需求与可执行验收

| 编号 | 范围与验收条件 |
| --- | --- |
| CLEAN-01 | 提供六种单次操作：清理每行首尾空白（默认）、删除空白行、按行去重、按行升序、按行降序、普通文本批量替换；选择操作后点击处理，不自动串行加工，不覆盖原输入 |
| CLEAN-02 | 识别 CRLF、CR、LF 并统一输出 LF；行操作把结尾换行后的空串视为一行；清理空白使用 ECMAScript trim 规则，不改变行内空格；删除空白行仅删除 trim 后为空的行，其他行原样保留 |
| CLEAN-03 | 去重按整行精确比较，区分大小写和首尾空白，保留第一次出现及原顺序；不静默 trim；输入 `甲\n乙\n甲` 输出 `甲\n乙`，`A\na\nA ` 保留三行 |
| CLEAN-04 | 升降序采用固定 UTF-16 字符串字典顺序，区分大小写，空行参与排序；不宣称按中文拼音、自然数字或设备语言排序；相等行保持原顺序，输入 `b\na\n10\n2` 升序为 `10\n2\na\nb` |
| CLEAN-05 | 批量替换使用非重叠、区分大小写的普通文本匹配，不支持正则；查找不能为空，替换允许为空；`$&`、`$1` 等是字面文本，不作替换语法。源输入、查找及替换的 CRLF/CR 先统一为 LF；`aaaa` 查找 `aa` 替换 `b` 输出 `bb` |
| CLEAN-06 | 主输入最多 100000 UTF-16 码元，查找与替换各最多 1000，结果最多 1000000；不截断；预先估算替换结果，超限时保留全部输入、中文提示且不保留旧结果；空输入显示无内容，非空内容处理后为空则明确显示“结果为空”，不误称失败 |
| CLEAN-07 | 提供当前操作说明、示例、清空和只读结果；只在成功且非空时允许复制，复制完成才提示成功，失败支持手动复制；编辑任一输入/操作使旧结果及异步复制提示失效；输入法组合期间不执行转换 |
| CLEAN-08 | pagehide、清空、卸载释放内容引用；内容不进入 URL、日志、分析事件、存储或网络。默认不读取剪贴板，不新增依赖、后端、文件导入导出、历史记录或持久化；保留既有 2FA 文档隔离与广告关闭范围 |
| CLEAN-09 | 首页、办公分类、搜索和相关工具提供真实试用入口；独立元信息、使用指南、SSG 正文和 noindex，不扩大既有八页正式索引白名单；精确更新页面/工具数量检查 |
| CLEAN-10 | 输入有可见标签、操作有说明，错误与结果状态可被读屏感知；375/768/1440px 无页面级横向溢出，键盘可选择/处理/清空/复制，错误不破坏输入 |

## 排除与待确认

不包含拼音/自然排序、大小写忽略去重、正则替换、富文本、Word/PDF/Excel 文件处理、远端接口和新依赖。CSV/JSON 表格互转与日期计算为候选后续模块，未纳入本规格授权。

请确认是否优先实现本模块及 CLEAN-01～10 范围。依据仓库 SDD 要求，规格审阅并明确授权后再编码。关联：[设计](design.md)、[任务](tasks.md)。

## 2026-11-06 实现授权

负责人明确选择“开发已拟定规格的文本整理工具”，本轮据此实现 CLEAN-01～10，解除此前优先级搁置。六种单次操作、精确去重、固定 UTF-16 排序及字面替换沿用上述范围，不新增依赖或数据上传。当前基线为 10 工具、17 站点页面加 404；实现后为 11 工具、18 站点页面加 404。正式八页索引白名单、敏感文档边界和广告关闭策略不变。生产候选、打包与部署不包含在本次授权内。

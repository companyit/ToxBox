# 053设计

关联[规格](spec.md)。现有fileText读取器用于逐行对比，会去除BOM并规范化换行、套用5000行限制，不能直接用于严格JSON原文导入。新增纯TS jsonFile模块（文件元信息校验与严格UTF-8解码）及小型同源jsonFile.worker，不改变文件对比机制。采用TextDecoder fatal:true、ignoreBOM:true保留BOM，100000码元复用JSON_DIFF_INPUT常量；JSON结构解析仍由原jsonDiff.worker执行。

页面每侧维护reading、来源元信息、固定提示以及reader/超时/版本。选文件先清空原生input值方便重选，启动读取并invalidate原比较；保留编辑值至成功。成功时先停reader，再写入对应编辑值及来源，不自动启动比较。错误或取消仅更新读取提示。编辑事件只取消对应reader、清除该侧来源；双方文本watch继续使原比较结果失效。单侧读取成功不应取消另一侧读取。

比较/交换/示例在加载中禁用，导入按钮在IME中禁用，清空仍走既有IME保护。compositionstart接收侧别、停止该侧读取；交换同时交换来源与提示。release先停止全部reader，再复用原清理流程。错误只用稳定代码映射，不回显原始异常；文件名仅通过文本绑定显示，可换行不进入报告/URL/日志。

验证纯模块边界、UTF-8/原文/BOM/空内容与大整数；组件模拟双worker迟到、重选、编辑、失败重试、取消、超时、交换、IME与离页，原结构比较/复制流程回归。浏览器以真实文件验证三宽度两引擎原文/精度/混合输入、读取失败保留、同名重选、非法JSON修复及隔离。类型/preview、单元/组件/静态及相关E2E通过后归档；Firefox/真实系统选择/辅助技术单独记录，不代签部署。

原文状态保留CR/CRLF；原生textarea的显示与value读取遵循浏览器换行规范化。验证同时断言可见文本为LF、发送比较Worker的内存原文仍含CRLF，避免用DOM显示反推读取模块丢失原文。用户继续编辑后使用编辑器实际内容。

# 009 2FA 设计提案

关联：[需求](spec.md)、[任务](tasks.md)。

## 边界与数据流

独立 TypeScript 算法模块负责严格 Base32 解码、时间计数器、Web Crypto HMAC-SHA-1 与动态截断。异步函数参数显式传入时间，算法无 DOM、请求或存储操作；组件负责输入、状态、倒计时、剪贴板及中文提示。Web Crypto 需要能力检查，不引入依赖。

视图状态：空输入 → 编辑 → 计算 → 运行/错误；每次编辑、清空、卸载增加计算版本号，丢弃过时 promise。计时器只在运行状态存在，每次由 Date.now 计算时间窗而非累计减秒；恢复可见时立即重算，计算失败立即移除过期验证码。

## 第三方脚本边界

现站已接入 GA。只排除 page_view 无法阻止同一文档已经加载的第三方脚本访问敏感输入。拟在进入或离开 2FA 页时使用整页导航；在 main 客户端启动时先判断敏感路径，再决定不初始化 GA。还需检查路由直接跳转、浏览器前进后退、含 query/hash 以及路径规范化，避免通过 SPA 导航绕过隔离。移除 script DOM 节点不是卸载方案。此行为变更需随规格确认，不直接扩大为全站统计关闭。

## 接入与验证影响

复用 ToolPageLayout 和现有页面样式。扩展页面目录、路由、工具目录与工作区布局。当前 SSG 与生产发布校验多处固定 8 页面/9 HTML；须针对新增页面修订准确集合和测试，不简单放松计数。保留当前用户发布脚本改动，最小补充。正式 SEO 白名单与站点配置另行确认，不将新增目录等同允许索引。

采用 RFC 已知向量（含时间窗边界和前导零）验证算法，补非法 Base32、异步竞态、卸载、复制失败、时钟跳变与后台恢复。浏览器检查敏感页直接打开和双向跨页导航，拦截请求确认无 GA 初始化及无密钥/验证码；类型检查、CSR/SSG 构建及相关回归均需记录真实结果。

负责人回复“本地 TOTP 验证码生成工具（推荐）”，结合前轮“可以开始添加2fa”授权，按本文本地工具范围实施，采用已提出的独立文档隔离方案。OTP-01～07 已有本地实现与验证，不代表生产发布或全浏览器验收。密钥只在当前页内存中处理，pagehide、清空和组件卸载均清理引用与定时器；不承诺物理擦除。新页面 noindex，正式索引集合仍为原 8 页。详细证据见 [验证记录](../../verification/009-totp.md)。

## T07 补验设计（2026-11-02）

使用 fake timers 验证恢复可见时重算、时钟后退和过期瞬间复制拒绝；安全计算失败保留输入并抑制内部错误。新增持久 E2E 用例覆盖 RFC 固定时间结果、密钥显隐、非法输入、跨页新文档及返回后清空、安全能力不可用。E2E 构建清单更新为精确 10 HTML，首页断言更新为 4 张卡片，保留原几何与焦点检查。历史迁移 154 身份与新增测试分开计数，历史 SHA 校验继续保留。

## otpauth 扩展设计

独立纯 TypeScript 解析模块输出已验证密钥、算法、位数、周期和文本元数据。先限制原始长度和控制字符、严格单轮百分号/UTF-8 解码，再用 URL 模型及唯一参数白名单验证；URL 解析异常转换固定中文错误，不泄露原输入。label 与 query issuer 同时存在时必须一致。不使用 innerHTML。

算法保持现有前三参数 API，第四参数接受类型化参数，独立执行运行时校验。组件状态以单个参数对象原子替换；导入、编辑、清空及离页使旧 promise 失效。全流程按参数周期计算时间窗；既有手动密钥入口行为保持默认参数。增加 RFC SHA256/SHA512 向量、严格解析错误矩阵、失败不覆盖、参数传播与清空的测试，再验证浏览器导入后结果及倒计时。

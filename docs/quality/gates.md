# 双层质量门禁（正式批准）

起草日期：2026-10-10。来源：项目负责人 M1-02 UAT 归档与双层质量门禁请求。关联 [ADR-014](../architecture/decisions.md)、[M1-02 证据](../verification/M1-02-text-statistics.md)。批准日期：2026-10-10，批准者：项目负责人，依据本轮明确授权。用于区分后续开发阶段与发布阶段，不追认任何未执行检查通过，不修改既有统计语义或验收数值。

## Dev Done — 开发完成

| 门禁 | 条件 | 最低记录 |
| --- | --- | --- |
| DD-01 | 已授权范围内功能符合规格 | 需求—任务—验证映射、实际结果；发布环境覆盖和定量发布验证的缺口单列，不写成全部需求通过 |
| DD-02 | 自动化测试通过 | 实际命令、数量、结果、被测版本；模拟渲染器不替代浏览器 |
| DD-03 | TypeScript 检查通过 | 实际命令及结果 |
| DD-04 | 生产构建通过 | 实际命令及结果；构建不是部署 |
| DD-05 | 核心交互通过真实浏览器验证 | 浏览器证据及负责人 UAT 来源；注明环境和覆盖不足 |
| DD-06 | 没有已知阻塞性缺陷 | 缺陷清单、修复复验结果或无已确认缺陷的范围说明 |
| DD-07 | 遗留验证明确记录 | 未测项目、影响、后续关闭条件；阶段审阅结论 |

开发完成允许仍有明确登记的发布验证缺口，不等于原规格的完整多环境验收已通过。已发现的统计错误、输入丢失、隐私泄漏、核心交互不可用等阻塞性缺陷不得移到发布阶段绕过。每个阶段由负责人结合证据确认；证据不足时保持待确认。

## Release Ready — 发布就绪

必须先满足全部 Dev Done 条件，再满足以下条件。

| 门禁 | 条件 | 证据要求 |
| --- | --- | --- |
| RR-01 | 目标浏览器兼容性 | Chrome、Edge、Firefox、Safari 验收时最新与前一稳定主版本，记录版本、系统和结果 |
| RR-02 | 正式移动设备与响应式 | 实际手机型号、浏览器、系统、视口/方向及布局操作记录；桌面模拟视口另列 |
| RR-03 | 无障碍 | 完整键盘、200% 缩放、实际读屏、对比度及反馈状态记录 |
| RR-04 | 隐私及安全 | 实际运行时请求、日志、URL、存储、输入渲染和异常路径核查；范围明确 |
| RR-05 | 性能预算 | 按工具规格保留设备、样本和逐次测量；Lighthouse 90 分以上仍为初步优化目标，不自动转为硬性预算 |
| RR-06 | 独立 URL 与 SEO | 正式工具 URL、元数据、直达/刷新/返回、托管回退及预渲染评估；需另获实现授权 |
| RR-07 | 生产部署前检查 | 正式域名、基础路径、构建产物、缓存/回退等检查及发布审批；本门禁不授权部署 |

## 证据与迁移规则

“负责人反馈通过”与“完整可复核验收通过”分开记录。缺失执行日期、版本、设备或测量数据均写未提供；接收日期不冒充执行日期。失败登记复现步骤、证据和等级；未测保持待验证，不等于失败。安全或核心可用性失败阻塞两层门禁，强制发布条件未满足阻塞 Release Ready，额外视觉便捷性才可列优化。

本规则已批准，用于后续开发/发布阶段。M1-02 的 Dev Done 已于 2026-10-10 经本次证据核对确认；原 002 I05、V02～V06 和 001 未关闭的完整验收任务保留，不能由新门禁自动勾选。既有 spec/design 的数值、兼容性和发布边界不变，完整验收与开发阶段确认分别记录。

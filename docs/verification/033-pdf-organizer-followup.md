# 033 后续补验与预览失败修复

日期：2026-11-07。负责人要求“继续往下推动”，本轮补齐特殊图像/字体资源实际解码，修复发现的空白缩略图错误，并整理当前19工具人工验收与032证据。范围仍为ORG-02/06/08及既有功能验收；无新增依赖、生产打包或远端操作。

## 问题及修复

合成4001×4001像素声明的图像超过预览16,000,000像素保护时，PDF.js会发送操作流错误，但render及getOperatorList的Promise可能先成功解决。原实现只等待渲染Promise，因而把不完整页面提交为空白缩略图。仅增加getOperatorList等待仍不足以拦截该场景，两浏览器复现一致。

`src/utils/pdfPreview.ts`现在在自有Worker端口先监听已锁定6.5.438的流错误标记（ERROR=5，以及失败的START/PULL完成消息），渲染前后核对错误代次；不读取/记录reason。另核对图像绘制操作的解码对象，拒绝null失败对象。失败页不沿用部分解析缓存，旋转也不把失败恢复成空白成功。`PdfOrganizerPage.vue`的重试会创建全新预览会话，保留文件与编辑计划。

这是明确绑定PDF.js6.5.438内部协议的兼容保护，运行时版本不符即拒绝预览；以后升级必须重新核验协议与失败路径。并发错误采用保守判定，可能让同期另一任务也提示重试；不把可疑部分图像当完整预览。正常空白页没有图像/流错误，仍允许预览和导出，不使用“白色像素=失败”的规则。
